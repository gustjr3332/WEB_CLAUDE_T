# Google Apps Script 배포 방법

구글 계정 인증이 필요한 단계이므로 아래 과정은 직접 진행해 주세요.

1. 스프레드시트 열기: https://docs.google.com/spreadsheets/d/1MOCGapRs-sc1civpI3wwV0BsYm85gMSTKsHoZOVmHJA
   (`gustjr3332@gmail.com` 계정으로 접근 권한이 있어야 합니다.)
2. 메뉴에서 **확장 프로그램 → Apps Script** 클릭.
3. 기존 `Code.gs` 내용을 전부 지우고, 이 폴더의 `Code.gs` 내용을 붙여넣기.
4. 상단 **배포 → 배포 관리** 클릭 → 기존 배포 옆 연필(✏️) 아이콘 → **버전: 새 버전** 선택 → **배포**.
   (처음 배포하는 거라면 **배포 → 새 배포**로, 유형은 **웹 앱** / 실행 권한 **나** / 액세스 **모든 사용자**로 설정)
5. `config.js`의 `APPS_SCRIPT_URL`은 URL이 바뀐 게 아니라면 그대로 두면 됩니다.

## ⚠️ 2026-08 구조 개편: 더 이상 1분 트리거가 필요 없습니다

이전 버전은 클릭마다 즉시 서버로 보내고 1분 트리거(`aggregateAndClearPending`)가 이를
합산하는 구조였습니다. 이번에 **브라우저가 하루치를 localStorage에 모아뒀다가 19:00
한 번에 배치로 전송**하는 방식으로 바뀌면서, 그 트리거는 더 이상 코드에 존재하지 않습니다.

기존에 `createTrigger`로 트리거를 등록해두셨다면, 코드에서 함수가 사라졌기 때문에
매분 실행 시도 → 실패 → 오류 알림 메일이 쌓이게 됩니다. **한 번만** 아래를 실행해 정리하세요.

1. 함수 선택 드롭다운에서 **`removeOldTrigger`** 선택 → **실행(▶)**
2. 왼쪽 시계 아이콘(트리거)에서 목록이 비어 있으면 성공.

## 시트 구조

| 시트 | 컬럼 | 의미 |
|---|---|---|
| `LIKE` | Date, PostID, PostTitle, LikeCount, LastUpdated | 정규화된 원본 데이터 (날짜+포스트 단위). 내부용이라 기본적으로 숨김 처리해둠 |
| `일별 좋아요 집계` | 날짜, 오늘의 총 좋아요 수, 최다 좋아요 포스트 | **실제로 보는 화면.** `LIKE`를 매번 다시 훑어 계산한 결과로 덮어씀. "최다 좋아요 포스트" 칸에는 `제목 (N개)` 형식으로 개수까지 같이 표시됨 |

### ★ 기존 데이터 이전 (한 번만 실행)

이전 스키마는 `LIKE` 시트에 `Hour` 컬럼이 있었습니다 (시간 단위 집계용). 이번에 하루 1회
배치 전송으로 바뀌면서 시간 단위 정보가 더 이상 의미가 없어져 `Hour` 컬럼을 없앴습니다.
기존에 쌓인 데이터를 날짜+포스트 단위로 합쳐서 옮기려면:

1. 함수 선택 드롭다운에서 **`migrateDropHourColumn`** 선택 → **실행(▶)**
2. 실행 로그에 "이전 완료: LIKE N행(날짜+포스트 단위), 일별 집계 M일 재계산됨." 이 보이면 성공.
   (이미 새 스키마면 "옮길 필요 없이 그대로 둡니다"라는 로그만 남기고 아무것도 바꾸지 않습니다.)

### ★ LIKE 탭 숨기기 (선택, 한 번만 실행)

화면에는 `일별 좋아요 집계`만 보이면 되므로, 원본 데이터인 `LIKE` 탭(과 예전 버전에서
쓰던 `Pending` 탭이 남아있다면 그것도)을 숨깁니다.

1. 함수 선택 드롭다운에서 **`hideRawDataSheet`** 선택 → **실행(▶)**

숨긴다고 데이터가 지워지는 건 아니라서, 필요하면 시트 하단 탭 목록에서 우클릭 →
"숨기기 취소"로 언제든 다시 볼 수 있습니다. `Pending` 탭은 이제 아예 쓰이지 않으니
확인 후 완전히 삭제하셔도 됩니다.

## 데이터 계약 (doPost)

`script.js`가 매일 19:00에 보내는 요청 본문:

```json
{
  "date": "2026-08-23",
  "posts": {
    "post-1": { "title": "정적 웹페이지로 좋아요 집계 시스템 만들기", "count": 3 },
    "post-2": { "title": "localStorage와 쿠키, 언제 무엇을 쓸까", "count": 1 }
  }
}
```

- `date`는 클라이언트가 계산한 "19:00 기준 버킷 날짜"를 그대로 신뢰해서 씁니다. 실제로
  좋아요가 눌린 날짜를 아는 건 클라이언트뿐이고, 서버 수신 시각을 쓰면 오히려 하루씩
  밀려 보일 수 있기 때문입니다.
- 이 계약을 지키는 요청이면 어디서 보내든 똑같이 동작합니다.

## 동작 확인
- 브라우저에서 웹 앱 URL을 그냥 열어보면(`GET` 요청) `{"status":"ok", ...}` 응답이 보이면 배포가 정상입니다.
- 블로그 페이지에서 LIKE를 눌러도 시트에는 바로 반영되지 않는 게 정상입니다 (19:00까지 브라우저에만 쌓임).
- 테스트하려면 컴퓨터 시계를 19:00 근처로 바꾸거나, `script.js`의 `SEND_HOUR` 값을 잠깐 현재 시각으로
  바꿔서 확인해보세요 (테스트 후 다시 19로 되돌리는 것 잊지 마세요).

## 코드를 수정한 경우
`Code.gs` 내용을 바꿨다면 **배포 → 배포 관리 → 수정(연필 아이콘) → 새 버전으로 배포** 를 눌러야 웹 앱 URL(doPost/doGet)에 변경사항이 반영됩니다. (URL 자체는 바뀌지 않습니다.)
